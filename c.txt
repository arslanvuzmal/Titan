feat(crm): real dashboard reading /api/v1, plus a live-discovery seed script

Replaces the fabricated demo with a CRM that shows only what the backend
actually holds.

apps/web/src/lib/titan.ts + apps/web/src/app/crm/page.tsx: a typed client and a
dashboard where every figure comes from /api/v1. There is deliberately NO
fallback to sample data on error -- a failed request renders an error state,
because a dashboard that invents numbers when the backend is down is worse than
one that says so. That was exactly the pre-0.2 failure mode.

The page leads with the sending posture, so an operator sees the four preflight
blockers before anything else. Empty states explain WHY something is empty
rather than padding: a lead that has not been crawled has no findings, and
displaying none is the correct answer.

titan/seed.py discovers real businesses through the live Google Places API and
records them with provenance and licensing metadata. It does not crawl and does
not send: seeded workspaces and campaigns are pinned to research_only, and the
sender identity is created with spf_ok/dkim_ok/dmarc_ok FALSE, because those
flags are set by real DNS verification and never by a seed script.

Verified against a running stack: 12 real Manchester dental practices
discovered live, visible through the API and the CRM. tsc --noEmit clean.
